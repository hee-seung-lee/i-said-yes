# 식장까지 업고 튀어 (2팀)

바가지는 막고, 예산은 지키고, 끝없는 고민은 결정으로 바꿔주는 결혼 준비 에이전트.
당사자가 지쳐도 견적 비교부터 일정 관리까지, 식장에 들어가는 그날까지 업고 뛰며 하드캐리합니다.

> 문구는 `src/brand.ts` 한 곳에서 바꾼다.
>
> 저장소 이름 `i-said-yes`: 프러포즈에 "응!" 하고 들뜬 그 마음. 앗싸, 나 결혼해요!

구성은 두 부분이다.

1. **01~03 조원 의견 시안**: 사전 체크리스트 → 결과 3안 → 지도. 대화형·카드형 **조각(페이지)** 으로 만들어 조원 의견을 모은 뒤 이어 붙인다.
2. **04~09 PRD 구현**: `docs/wedding-agent-flow.md` 의 화면(오늘 할 일·전체 타임라인, 견적 비교, 결정 도우미, 예산, 본식 체크)과 계산 규칙·데이터 모델·JSON 가져오기/내보내기.

## 실행

```
npm install
npm run dev     # http://localhost:5173
npm test        # 계산 규칙·PRD 수용 기준 테스트
npm run build
```

## 조각 이름 규칙: `단계_타입_기능`

| 조각 | 단계 | 내용 |
|---|---|---|
| `01_chat_checklist` / `01_card_checklist` | 01 사전 체크리스트 | 20문항(대화형 / 카드형) |
| `02_chat_plans` / `02_card_plans` | 02 결과 3안 | 취향·예산·일정 우선 3안 |
| `03_chat_map` / `03_card_map` | 03 지도 | 고른 안 업체 위치 |
| `04_chat_timeline` / `04_card_timeline` | 04 오늘 할 일·타임라인 | D-day 역산, 달력, 업무 상세 편집, 압축 계획, 선행 관계, 제안 마일스톤 |
| `05_card_quotes` | 05 견적 비교 | 후보 최대 3곳, 확정 총액 / 확인된 최소금액, 문의 초안 |
| `06_card_decide` | 06 결정 도우미 | PRD 흐름도 단계, 추천 1개·대안·이유, 보류(막힌 기준·재검토일), 계약 확인 |
| `07_card_budget` | 07 예산 | 총예산·예비비·포함 범위, 예상 비용·지급·잔금, 초과 지급 |
| `08_card_dayof` | 08 본식 체크 | 마지막 주 할 일, 업체 최종 확인, 준비물, 당일 진행표 |
| `09_card_data` | 09 데이터 | JSON 내보내기·가져오기(중복 방지, 병합 미리보기), 초기화 |

- 파일 `src/pages/<조각>.tsx`, 경로 `#/<조각>`, 목록 `src/pieces.ts`. 04 부터는 아래쪽 탭으로 오간다.
- 첫 화면(`#/`)의 조립기에서 01~04 단계별 타입을 고르면 그 조합으로 흐름이 이어진다.
- 새 조각 추가: `src/pages/` 에 파일 → `pieces.ts` 한 줄 → `App.tsx` 라우트 한 줄.

## 정한 것 (PRD 에 없거나 해석이 필요했던 부분)

- 금액은 원 단위로 저장하고 화면 입력은 만 원으로 받는다.
- `sourceUrl` 은 조원 개인 Notion 이라 seed 에서 비웠다. 가져오기 때 들어오면 중복 판정에 쓴다.
- 원본 날짜(`originalStartDate/EndDate`)는 seed 에 넣지 않고, 가져올 때도 버린다.
- 필수 여부는 사용자가 정한다. 체크리스트 답(DVD 안 함, 주례 없음 등)은 "선택으로 바꿀까요?" 제안만 한다.
- 제안 선행 관계(예약 확정은 T07 먼저, 의상 투어 → 계약 → 가봉, 포토테이블은 보정본 수령 먼저 등)는 모두 미확인으로 시작한다.
- 압축 계획은 '지금 진행'으로 고른 일을 오늘~본식 전날 사이에 최대 2주 간격으로 배치해 확정 날짜로 넣는다.
- 당일 진행표 시각과 준비물 목록은 일반적인 예시라 예식장 안내를 우선한다.

## 사전 체크리스트

`src/data/questions.ts` 에 조 자료 `table.tsv` 의 20문항을 옮겼다. 모두 선택 입력이다. 3안 계산에 쓰는 항목은
`recommend.ts` 의 `K` 에 모여 있다(총예산·최대 한도, 생략 가능 항목, 예식 지역, 예식장 분위기·필수 조건, 별도 촬영지,
드레스 소재, 드레스샵 방문 지역). 예산 화면의 "체크리스트 값 가져오기"가 총예산·예비비를 쓴다.

## 데이터와 한계

- 01~03 의 업체·가격·위치는 `src/data/vendors.ts` 의 **예시 데이터**다. 견적 화면에서 "예시"로 시작한 후보에도 표시된다.
- 지도는 OpenStreetMap 타일(키 없음). 외부 이미지를 막는 게시 환경에서는 위치 점만 보인다.
- 실제 업체 검색, Notion 동기화, AI 연결, 계약·결제·업체 연락은 하지 않는다. 문의 초안만 만든다.
- 저장은 브라우저 localStorage 에만 된다. 다른 기기로는 09 데이터 화면의 JSON 으로 옮긴다.
