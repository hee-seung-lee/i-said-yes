# 식장까지 업고 튀어 (2팀)

바가지는 막고, 예산은 지키고, 끝없는 고민은 결정으로 바꿔주는 결혼 준비 에이전트.
당사자가 지쳐도 견적 비교부터 일정 관리까지, 식장에 들어가는 그날까지 업고 뛰며 하드캐리합니다.

> 문구는 `src/brand.ts` 한 곳에서 바꾼다.
>
> 저장소 이름 `aisle-carry`: 버진로드(aisle)까지 하드캐리(carry)한다는 뜻.

사전 체크리스트 → 결과 3안 → 지도 흐름을 **조각(페이지)** 단위로 만들었다.
조원 의견을 모은 뒤 단계마다 마음에 드는 조각을 골라 이어 붙인다.

## 실행

```
npm install
npm run dev     # http://localhost:5173
npm test        # 추천 규칙 테스트
npm run build
```

## 조각 이름 규칙: `단계_타입_기능`

| 조각 | 단계 | 타입 | 기능 |
|---|---|---|---|
| `01_chat_checklist` | 01 사전 체크리스트 | 대화형 | 말풍선으로 하나씩 묻기 |
| `01_card_checklist` | 01 사전 체크리스트 | 카드형 | 타일 카드 넘기기 |
| `02_chat_plans` | 02 결과 3안 | 대화형 | 말풍선 속 3안 카드 |
| `02_card_plans` | 02 결과 3안 | 카드형 | 탭·스와이프로 한 안씩 |
| `03_chat_map` | 03 지도 | 대화형 | 말풍선 속 지도·다음 할 일 |
| `03_card_map` | 03 지도 | 카드형 | 큰 지도 + 바텀시트 |

- 파일: `src/pages/<조각>.tsx`, 경로: `#/<조각>`, 목록: `src/pieces.ts`
- 첫 화면(`#/`)의 조립기에서 단계별 타입을 고르면 그 조합으로 흐름이 이어진다
  (예: `01_card → 02_chat → 03_card`). 답변·선택은 공유 상태(`src/store.ts`, localStorage)라
  어느 조합이든 그대로 넘어간다.
- 새 조각 추가: `src/pages/` 에 파일 → `pieces.ts` 한 줄 → `App.tsx` 라우트 한 줄.

## 사전 체크리스트

`src/data/questions.ts` 에 조 자료 `table.tsv` 의 20문항을 옮겼다. 문항마다 세부 항목이 입력 필드(선택 칩·숫자·메모)이고
모두 선택 입력이다. 3안 계산에 쓰는 항목은 `recommend.ts` 의 `K` 에 모여 있다
(총예산·최대 한도, 생략 가능 항목, 예식 지역, 예식장 분위기·필수 조건, 별도 촬영지, 드레스 소재, 드레스샵 방문 지역).
나머지 항목은 저장만 하고 이후 일정·견적 기능에서 쓴다.

## 데이터와 한계

- 업체·가격·위치는 `src/data/vendors.ts` 의 **예시 데이터**다. 실제 업체 DB 나 지도 API 를 붙일 때 이 파일과
  `src/components/PlanMap.tsx`(현재 OpenStreetMap)만 바꾼다.
- 추천은 `src/logic/recommend.ts` 의 규칙 계산이다(AI 아님). 취향 우선 / 예산 우선 / 일정 우선 3안,
  추천 1개 = 조건 일치 최다, 같으면 저렴한 안.
- 추가금 미확인 업체가 있으면 "확인된 최소금액"만 보여 주고 예산 안이라고 단정하지 않는다(PRD 비용 규칙).
- PRD 의 타임라인·견적 비교·예산·본식 체크 화면은 아직 없다. 이 조각 흐름과 별개로 붙인다.
